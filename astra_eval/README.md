# Astra evaluation packets

Does a coding agent (GPT-6 Astra in a Codex session; Claude Code as the second agent) do a stage of
our pipeline better, faster or cheaper than the stage we built? Three stages, one packet each:

| packet | the agent gets | our stage | our verifier |
|---|---|---|---|
| `p1_real2sim` | one RGB-D capture (+ phone video if we have one), the sled scene JSON format | Gemini -> SAM 2 -> SAM 3D | tape-measured sizes and poses (cm); twin loads; sled plan succeeds from the scene |
| `p2_motion` | the twin's robot definition, the 9 sled actions with their grasp poses and obstacle worlds | cuRobo layer (`twin/newton/motion.py`) | our cuRobo collision check on its joint trajectories, endpoint error, joint limits, continuity |
| `p3_tamp` | goal sentence, scene, the executor with its CLI (repo access) | `tamp_sym.py` A* + Newton rollouts | the goal audit (`sled_audit.json`) on the same executor |

This is not a reproduction of RoboSimStudio or any paper. Those works are evidence that agents can
build scenes; the question here is what an agent adds *inside our pipeline*, judged by our verifiers.
The big goal stays TAMP integrated (motion inside the task search, executor following the planned
trajectories): these packets must not displace it.

## Rules, the same for every packet

- The agent gets exactly the packet directory (`PROMPT.md`, `FORMAT.md`, `inputs/`) and nothing
  else, except p3, which gets the repo because it has to drive our executor. Blind otherwise:
  a run that reads our code for the stage under test is void.
- One fixed prompt per packet; a fixed budget (wall time, tokens, interventions). No hints during
  the run. A human answer to a question counts as an intervention and is logged verbatim.
- Three runs per agent per packet. Agent runs do not repeat; one run is an anecdote.
- The verifier is ours and never the agent's own checks. Scores come from `score.py` / `verify.py`.
- Each run is logged with `common/runlog.py` (agent, model, start/end, wall s, tokens if the CLI
  reports them, interventions, outcome) into `runs/<packet>/<agent>_<n>/`.
- GPU: one 24 GB card shared with everything else. Runs happen in a git worktree
  (`common/run_agent.sh`), never on `main`; the agent must never kill processes or clear caches.

## Running an agent

```bash
# Codex (needs `codex` on PATH and an OpenAI login with Astra access)
astra_eval/common/run_agent.sh codex p1_real2sim 1
# Claude Code as the second agent
astra_eval/common/run_agent.sh claude p1_real2sim 1
```

The script makes `runs/<packet>/<agent>_<n>/` with a worktree, copies the packet in, starts the
agent with `PROMPT.md`, and records start and end. Then score:

```bash
NEWTON_PY=~/miniforge3/envs/newton-1.5/bin/python
$NEWTON_PY astra_eval/p1_real2sim/score.py --scene runs/p1_real2sim/codex_1/out/scene.json --gt astra_eval/p1_real2sim/inputs/gt.json
$NEWTON_PY astra_eval/p2_motion/verify.py  --traj  runs/p2_motion/codex_1/out/trajectories.json
$NEWTON_PY astra_eval/p3_tamp/score.py     --run   runs/p3_tamp/codex_1
```
